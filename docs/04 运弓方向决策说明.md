# 运弓方向决策说明

> 这份文档针对 `violin_midi_json` 中新增的运弓方向决策模块，详细说明它的决策逻辑、层次结构、文件安排，以及如何使用。

本文档更新自先前版本，反映近期对方向决策、编码器协议及 MATLAB 仿真所做的重要改动：加入 per-note `bow_speed`、编码器在包级别标示连奏延续（把 LEGATO 标志写到前一包以指示连续行程），以及仿真中对连奏段合并（merge-legato-segments）以产生连续的 S 型行程。
---

额外目标（本次改动）：
- 提供每音符的 `bow_speed`（写入协议），使硬件能按音符期望速度调整；
- 在二进制协议层用包级信号告诉接收端“下一音与本包属于同一连续行程”，以避免硬件在连奏间复位弓头；
- 在 MATLAB 仿真中按“连奏段”生成单次连续 S 曲线，避免因按音符生成独立 S 曲线导致的跳位。

当 MIDI 文件本身不包含连弓符号时，机器人需要根据音乐和机械规则自动判断运弓方向。
    THEN 判定为 Legato
注：决策器现在同时输出每音符的 `is_legato` 与 `bow_speed`，但编码器在打包时会根据后续音符的连奏属性，将连奏延续的信号写入“前一包”的 `LEGATO` 标志，以指示连续行程。
本模块的设计目标是：

  - `needs_reset_bow`
  - `bow_speed`（整数等级，映射到协议的低7位，通常 1..10）

关键点补充：
- `BowDecisionEngine.decide(...)` 会对每个 `ConvertedNote` 输出完整决策集：`bow_direction`、`is_legato`、`needs_reset_bow`、`bow_speed` 等。
- `bow_speed` 的计算会考虑音符时值、是否处在 legato 段（legato 时会适当降低速度等级以保持平滑）、以及可选的速度映射曲线（可在 `BowDecisionOptions` 中调整）。
- 为后续“智能识谱+显式连弓符号”留出接口；
本次改动使其：
- 先对所有音符运行 `BowDecisionEngine`（批量决策），以便有足够的前后文信息。
- 编码器在写入每个 12 字节包时会：
  - 将方向 (`bow_direction`) 写入 `byte 7` 的 MSB；
  - 将 `bow_speed` 写入 `byte 7` 的低 7 位（等级值）；
  - 将 `legato` 标志写入 `byte 9` 的 `LEGATO_FLAG`（0x04）。
  - 当后续音符被判定为与当前音符处于同一连续行程（即 `is_legato` 且方向相同）时，编码器会在**当前包**或**前一包**上设置 `LEGATO_FLAG`（实现细节：我们把“连奏延续”信号写在前一包的 flags，使接收端在收到该包后就知道下一包不应重置弓位）。
  - 保持 `RESET_BOW_FLAG`（0x08）用于显式指示需要重置弓头的情况。

该批量决策并前包标示的方法，避免了接收端按每个独立包立即回退或重置弓头，从而保证连奏时的连续运动。
## 2. 决策层次结构
本次修改中，`ConvertedNote` 仍包含 `is_legato` 字段，但 `converter` 默认不强行把 MIDI 当作显式连弓。隐式连奏由 `BowDecisionEngine` 输出并在编码阶段决定是否在包上设置连奏延续标志。

### 2.1 第一层：节拍与强弱律动规则

补充：已在模型中加入/保留 `bow_speed` 字段（整数），以便在编码器阶段直接读取并编码到包里。


协议要点（本次变更相关）：
- Byte0: Header (0xA5)
- Byte7: Bow byte — MSB: `direction` (1 = 拉/下弓, 0 = 推/上弓)，低7位: `bow_speed`（1..127，但建议 1..10 作为速度等级）
- Byte9: Flags — `LEGATO_FLAG` = 0x04（当设置在包上表示“此包之后的行程与下一包连续”）；`RESET_BOW_FLAG` = 0x08（需要复位弓位）

说明：编码器会在前一包的 `byte9` 上设置 `LEGATO_FLAG` 以指示“下一包续弓”，硬件应据此在收到当前包时准备保持行程连续。这个语义约定已在 MATLAB 仿真中实现为“段合并”策略。
- 该规则体现“重拍下弓、弱拍上弓”的自然演奏习惯。

该命令会：
1. 解析 MIDI；
2. 选指法；
3. 用 `BowDecisionEngine` 计算 `bow_direction`, `is_legato`, `bow_speed` 等决策；
4. 编码器对所有音符批量决策后生成 12 字节包流并写入 `test_output.bin`（在前一包上标注 `LEGATO_FLAG` 表示“下一包续弓”情况）。

### 2.3 第三层：隐式连音判定启发式

为了处理 MIDI 里没有 Slur 的情况，新增隐式连奏判定：

```text
IF 同弦
AND 时间间隔 <= 阈值
AND 音程跨度 <= 阈值
THEN 判定为 Legato
```

默认启发式阈值：
  6. 输出：下弓 / 上弓 + `is_legato` + `bow_speed` + `needs_reset_bow`
  7. 编码器批量读取所有决策后：在包级别（并可能在前一包的 flags）写入 `LEGATO_FLAG`，并把 `bow_speed` 编入包的低7位。
- 时间间隔 `Threshold_T`：约 0.03 s

- 协议布局仍为 12 字节；新增语义为：`byte7` 包含 `bow_speed`（低7位）与 `direction`（MSB），`byte9` 的 `LEGATO_FLAG` 可用于指示连奏延续（可能写在前一包以便提前通知接收端）。
- `ROS2` 与 Arduino 端的解码器无需改动数据结构，但需要在行为上遵守新的语义：当接收到带 `LEGATO_FLAG` 的包时，若该包指示下一包续弓，则接收端应在下一包到来时避免复位弓位，或直接在收到带 LEGATO 的前包时保持连续行程模式。
- MATLAB 仿真已改为按合并的 legato 段生成单次 S 型轨迹（`simu5_read_json.m`、`simu6_read_bin.m`），这与新编码器的前包 LEGATO 标示语义一致。


进一步建议（与本次变更直接相关）：
- 在 Arduino 固件中，增加对“前一包 `LEGATO_FLAG`”语义的处理注释与单元测试；
- 在 `violin_midi_json/tests/` 中添加端到端测试：生成 `.bin` → 由仿真脚本解析并验证连奏段是否被合并为单次连续行程；
- 对 `bow_speed` 映射曲线做硬件标定：把等级映射到实际电机速度/周期，以保证仿真与硬件一致。
- 这是一种“借弓/补偿”策略，保证连续方向决策时不发生弓位失控。

## 3. 主要实现文件

### 3.1 `violin_midi_json/src/violin_midi_json/bow_decision.py`

这是本次新增的核心模块，负责：

- 定义 `BowDecisionEngine` 和 `BowDecisionOptions`
- 封装节拍强弱、时值、隐式连奏和弓位约束逻辑
- 提供 `decide(...)` 接口，输出：
  - `bow_direction`
  - `is_legato`
  - `is_strong_beat`
  - `needs_reset_bow`
  - `beat_position`

#### 关键点

- `explicit_legato` 参数：当识谱模块检测到五线谱上的连弓时，可显式传入该值。
- `implicit_legato_detection` 参数：控制是否启用 MIDI 隐式连奏启发式。
- 如果 `implicit_legato_detection=False`，则只依赖显式连弓标记。

### 3.2 `violin_midi_json/src/violin_midi_json/binary_encoder.py`

该文件负责最终把每个音符编码成 12 字节数据包。

本次改动使其：

- 不再简单按 `is_legato` 翻转弓向；
- 而是先通过 `BowDecisionEngine` 计算出 `bow_direction`；
- 再把 `decision.is_legato` 写入协议标志位。

### 3.3 `violin_midi_json/src/violin_midi_json/converter.py`

`converter.py` 目前仍负责：

- 解析 MIDI
- 选指法
- 生成 `ConvertedNote`
- 输出 `ConversionResult`

本次修改中，`ConvertedNote.is_legato` 默认设为 `False`，
这样隐式连奏判定不会和数据模型混在一起，便于后续由识谱模块直接设置显式连弓。

### 3.4 `violin_midi_json/src/violin_midi_json/models.py`

其中的 `ConvertedNote` 包含字段：

- `start`, `end`, `duration`
- `pitch`, `note_name`, `string`, `position`, `finger`
- `velocity`
- `is_string_change`, `is_position_change`
- `is_legato`

当前 `is_legato` 字段仍保留，用于承载显式连弓或由决策器输出的连奏标志。

### 3.5 其他关联组件

- `violin_midi_json/src/violin_midi_json/constants.py`
  - 存放默认阈值和常量，如 `DEFAULT_LEGATO_GAP_SECONDS`、`DEFAULT_LEGATO_MAX_INTERVAL`。

- `docs/Binary_Violin_Event_Protocol_V1.md`
  - 说明 12 字节协议，弓向和 flags 的定义与本次逻辑直接对应。

## 4. 使用说明

### 4.1 生成二进制曲谱

在项目根目录执行：

```bash
python -m violin_midi_json.cli scores/twinkle/twinkle_full.mid test_output.bin --format bin
```

该命令会：

1. 解析 MIDI；
2. 选指法；
3. 用 `BowDecisionEngine` 计算 `bow_direction`；
4. 生成 `test_output.bin`。

### 4.2 关闭隐式连奏判定（后续识谱用法）

当前实现中，`BowDecisionOptions` 内置参数 `implicit_legato_detection=True`。
后续如果需要改成只读显式连弓标记，可将其设为 `False`。

例如：

```python
from violin_midi_json.bow_decision import BowDecisionEngine, BowDecisionOptions
options = BowDecisionOptions(tempo_bpm=120.0, implicit_legato_detection=False)
engine = BowDecisionEngine(options)
```

### 4.3 显式连弓输入方案

后续五线谱识别器可以在生成 `ConvertedNote` 时提供显式连弓信息：

- `explicit_legato=True`：表示五线谱中存在弧线连弓；
- `explicit_legato=False`：表示无连弓。

`BowDecisionEngine.decide(...)` 会优先使用 `explicit_legato`，并在必要时再做方向判断。

## 5. 决策流程示意

```text
[读取 MIDI / 五线谱音符]
       │
  1. 计算拍位与强弱（Beat Weight）
       │
  2. 如果有显式连弓标记 → 保持当前运弓方向
       │
  3. 否则如果启用隐式连奏判定 → 判定同弦短间隔小音程为连奏
       │
  4. 否则按节拍/时值/快音交替规则决定方向
       │
  5. 检查当前弓位是否越界 → 必要时强制纠偏
       │
  6. 输出：下弓 / 上弓 + legato 标志 + 下一个弓位估计
```

## 6. 结果备注

- 目前 `violin_midi_json` 的 `.bin` 协议仍沿用 12 字节布局；本次改动只影响 `byte 7` 的方向位和 `byte 9` 的 `legato` flag。
- `ROS2` 端与 Arduino 端的解码器均可继续使用已有的 `protocol.py` 和 `giga_serial_bridge.ino`，因为协议格式未改动。
- 该决策模块目前是“向前兼容”的：
  - 对于纯 MIDI 文件，它提供更智能的弓向决策；
  - 对于未来五线谱识别，它可以被配置为“只按显式连弓工作”。

## 7. 推荐后续优化点

- 在 `converter.py` 中增加 `ConvertedNote.explicit_legato` 字段，明确区分“显式连弓”与“隐式推断连奏”。
- 用 MIDI 解析器读出节拍信息，替代当前的 `start_seconds / seconds_per_quarter` 简化方式。
- 在本模块中加入 `bow_position` 估计输出，便于仿真和硬件同步。
- 在 ROS mock 和 Arduino ack 中打印 `bow_direction` + `legato` 结果，便于 end-to-end 验证。
