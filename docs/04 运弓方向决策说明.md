# 运弓方向决策说明

> 这份文档针对 `violin_midi_json` 中新增的运弓方向决策模块，详细说明它的决策逻辑、层次结构、文件安排，以及如何使用。

---

## 1. 目标

当 MIDI 文件本身不包含连弓符号时，机器人需要根据音乐和机械规则自动判断运弓方向。

本模块的设计目标是：

- 对“下弓/上弓”做规则化、可解释的决策；
- 把原来的“每个非 legato 翻转”逻辑抽象成独立层；
- 兼顾节拍重弱、时值、隐式连奏与弓位约束；
- 为后续“智能识谱+显式连弓符号”留出接口；
- 保证未来关闭隐式连奏判定时，不影响显式连弓的处理。

---

## 2. 决策层次结构

这套决策按照 4 层规则组织：

### 2.1 第一层：节拍与强弱律动规则

- 强拍（如小节首拍或次强拍）优先分配下弓（拉弓 / `BOW_DOWN`）。
- 弱拍或弱起音符优先分配上弓（推弓 / `BOW_UP`）。
- 该规则体现“重拍下弓、弱拍上弓”的自然演奏习惯。

### 2.2 第二层：音符时值与弓长平衡规则

- 长音优先下弓，以利用臂重保持音色稳定。
- 快音、短音更倾向上弓或交替弓，以避免弓用完。
- 连续等时值快音（如多个十六分音符）采用严格交替弓策略。

### 2.3 第三层：隐式连音判定启发式

为了处理 MIDI 里没有 Slur 的情况，新增隐式连奏判定：

```text
IF 同弦
AND 时间间隔 <= 阈值
AND 音程跨度 <= 阈值
THEN 判定为 Legato
```

默认启发式阈值：

- 时间间隔 `Threshold_T`：约 0.03 s
- 音程跨度 `Max_Interval`：7 半音以内

连奏时，保持上一音符方向不变；非连奏时再按规则决定是否换弓。

### 2.4 第四层：机械约束与弓位纠偏

机器人必须追踪当前弓位（`0.0 = 弓根`、`1.0 = 弓尖`），以避免“弓位越界”。

- 如果当前决策是下弓，但弓位已接近弓尖（如 `>0.85`），则强制纠偏为上弓。
- 如果当前决策是上弓，但弓位已接近弓根（如 `<0.15`），则强制纠偏为下弓。
- 这是一种“借弓/补偿”策略，保证连续方向决策时不发生弓位失控。

## 3. 主要实现文件

### 3.1 `violin_midi_json/src/violin_midi_json/bow_decision.py`

这是本次新增的核心模块，负责：

- 定义 `BowDecisionEngine` 和 `BowDecisionOptions`
- 封装节拍强弱、时值、隐式连奏和弓位约束逻辑
- 提供 `decide(...)` 接口，输出：
  - `bow_direction`
  - `is_legato`
  - `is_strong_beat`
  - `needs_reset_bow`
  - `beat_position`

#### 关键点

- `explicit_legato` 参数：当识谱模块检测到五线谱上的连弓时，可显式传入该值。
- `implicit_legato_detection` 参数：控制是否启用 MIDI 隐式连奏启发式。
- 如果 `implicit_legato_detection=False`，则只依赖显式连弓标记。

### 3.2 `violin_midi_json/src/violin_midi_json/binary_encoder.py`

该文件负责最终把每个音符编码成 12 字节数据包。

本次改动使其：

- 不再简单按 `is_legato` 翻转弓向；
- 而是先通过 `BowDecisionEngine` 计算出 `bow_direction`；
- 再把 `decision.is_legato` 写入协议标志位。

### 3.3 `violin_midi_json/src/violin_midi_json/converter.py`

`converter.py` 目前仍负责：

- 解析 MIDI
- 选指法
- 生成 `ConvertedNote`
- 输出 `ConversionResult`

本次修改中，`ConvertedNote.is_legato` 默认设为 `False`，
这样隐式连奏判定不会和数据模型混在一起，便于后续由识谱模块直接设置显式连弓。

### 3.4 `violin_midi_json/src/violin_midi_json/models.py`

其中的 `ConvertedNote` 包含字段：

- `start`, `end`, `duration`
- `pitch`, `note_name`, `string`, `position`, `finger`
- `velocity`
- `is_string_change`, `is_position_change`
- `is_legato`

当前 `is_legato` 字段仍保留，用于承载显式连弓或由决策器输出的连奏标志。

### 3.5 其他关联组件

- `violin_midi_json/src/violin_midi_json/constants.py`
  - 存放默认阈值和常量，如 `DEFAULT_LEGATO_GAP_SECONDS`、`DEFAULT_LEGATO_MAX_INTERVAL`。

- `docs/Binary_Violin_Event_Protocol_V1.md`
  - 说明 12 字节协议，弓向和 flags 的定义与本次逻辑直接对应。

## 4. 使用说明

### 4.1 生成二进制曲谱

在项目根目录执行：

```bash
python -m violin_midi_json.cli scores/twinkle/twinkle_full.mid test_output.bin --format bin
```

该命令会：

1. 解析 MIDI；
2. 选指法；
3. 用 `BowDecisionEngine` 计算 `bow_direction`；
4. 生成 `test_output.bin`。

### 4.2 关闭隐式连奏判定（后续识谱用法）

当前实现中，`BowDecisionOptions` 内置参数 `implicit_legato_detection=True`。
后续如果需要改成只读显式连弓标记，可将其设为 `False`。

例如：

```python
from violin_midi_json.bow_decision import BowDecisionEngine, BowDecisionOptions
options = BowDecisionOptions(tempo_bpm=120.0, implicit_legato_detection=False)
engine = BowDecisionEngine(options)
```

### 4.3 显式连弓输入方案

后续五线谱识别器可以在生成 `ConvertedNote` 时提供显式连弓信息：

- `explicit_legato=True`：表示五线谱中存在弧线连弓；
- `explicit_legato=False`：表示无连弓。

`BowDecisionEngine.decide(...)` 会优先使用 `explicit_legato`，并在必要时再做方向判断。

## 5. 决策流程示意

```text
[读取 MIDI / 五线谱音符]
       │
  1. 计算拍位与强弱（Beat Weight）
       │
  2. 如果有显式连弓标记 → 保持当前运弓方向
       │
  3. 否则如果启用隐式连奏判定 → 判定同弦短间隔小音程为连奏
       │
  4. 否则按节拍/时值/快音交替规则决定方向
       │
  5. 检查当前弓位是否越界 → 必要时强制纠偏
       │
  6. 输出：下弓 / 上弓 + legato 标志 + 下一个弓位估计
```

## 6. 结果备注

- 目前 `violin_midi_json` 的 `.bin` 协议仍沿用 12 字节布局；本次改动只影响 `byte 7` 的方向位和 `byte 9` 的 `legato` flag。
- `ROS2` 端与 Arduino 端的解码器均可继续使用已有的 `protocol.py` 和 `giga_serial_bridge.ino`，因为协议格式未改动。
- 该决策模块目前是“向前兼容”的：
  - 对于纯 MIDI 文件，它提供更智能的弓向决策；
  - 对于未来五线谱识别，它可以被配置为“只按显式连弓工作”。

---

## 7. 推荐后续优化点

- 在 `converter.py` 中增加 `ConvertedNote.explicit_legato` 字段，明确区分“显式连弓”与“隐式推断连奏”。
- 用 MIDI 解析器读出节拍信息，替代当前的 `start_seconds / seconds_per_quarter` 简化方式。
- 在本模块中加入 `bow_position` 估计输出，便于仿真和硬件同步。
- 在 ROS mock 和 Arduino ack 中打印 `bow_direction` + `legato` 结果，便于 end-to-end 验证。
