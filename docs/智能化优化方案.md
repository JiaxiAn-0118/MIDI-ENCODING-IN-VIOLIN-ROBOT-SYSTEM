# 小提琴机器人智能化优化方案

> 目标：让系统从“按预设参数播放 MIDI”升级为“理解乐句、规划动作、监听结果并持续修正”的智能演奏机器人。

## 1. 当前基础与核心判断

项目已经具备一条可运行的数字链路：

```text
MIDI
→ 音符解析
→ 弦 / 把位 / 手指映射
→ 12 字节 Violin Event
→ ROS 2 串口桥
→ Arduino
```

当前映射以单音、局部静态规则为主，控制参数主要来自预设表。这种方案适合快速打通硬件，但继续增加规则会很快遇到三个瓶颈：

1. **同一个音不只有一种演奏动作**：选弦、把位和弓段必须结合前后音符共同决定。
2. **相同指令不一定产生相同声音**：温湿度、松香、琴弦状态和机构间隙都会改变结果。
3. **“音准正确”不等于“演奏好听”**：音色、连贯性、重音、乐句呼吸也需要进入优化目标。

因此，智能化的重点不应是简单接入大模型，而应建立下面这个闭环：

```text
乐谱理解 → 全局动作规划 → 实时执行 → 声音 / 力 / 位置感知
    ↑                                          ↓
    └────────── 质量评价 ← 参数修正 ← 状态估计 ────┘
```

## 2. 总体架构：快慢双环

建议把智能系统拆成两个时间尺度，避免把不确定的 AI 推理直接放入实时控制环。

### 2.1 快环：毫秒级确定性控制

运行在 Arduino / ROS 2 实时节点，负责：

- 电机位置、速度、电流闭环；
- 弓压、弓速和换弦角度控制；
- 事件调度、超时处理和安全限位；
- 传感器采样、时间戳对齐；
- 异常时降级或急停。

快环必须可解释、可复现，不依赖云端模型。

### 2.2 慢环：音符级与乐句级智能决策

运行在上位机，负责：

- 乐句切分、力度和奏法推断；
- 全曲指法、换把、换弦和弓段规划；
- 根据上一遍演奏录音自动调参；
- 建立不同琴、弓、曲目和环境的参数档案；
- 生成下一遍演奏策略。

慢环可以使用搜索、优化、机器学习或多模态模型，但输出必须经过约束检查后才能进入快环。

## 3. 优先级最高的六项智能化升级

### 3.1 从“单音贪心”升级为“全曲动作规划”

当前 `choose_default()` 按优先级、把位、手指和弦名选择单个音的默认指法。建议把每个音的候选指法看作图节点，用动态规划、Viterbi 或 A* 搜索整段乐句的最低代价路径。

候选路径代价可定义为：

```text
J =
  w1 × 换弦次数
+ w2 × 换把距离
+ w3 × 手指跨距
+ w4 × 机构运动时间
+ w5 × 撞限位风险
+ w6 × 音色不一致
+ w7 × 乐句中断惩罚
```

规划器还必须满足硬约束：

- 执行机构能在下一个音开始前到位；
- 换弦角速度、滑轨加速度不超限；
- 同一时间不会产生机械冲突；
- 超出机器人音域或能力边界时明确报错；
- 空弦、换把、连弓等选择符合设定风格。

**近期可交付物：**

- `GlobalFingeringPlanner`：输入整首 `MidiNote`，输出全局最优 `ConvertedNote`；
- 输出每次选择的分项代价，便于调试；
- 同一曲目支持“最稳”“最少换弦”“接近真人”三种策略。

### 3.2 增加“弓法规划器”，让机器人开始像在拉琴

当前二进制协议已经预留弓向、弓速、弓压以及连奏、断奏、重音、震弓等标志，但这些字段尚未形成乐句级策略。建议新增 `BowPlanner`：

```text
音符时值 + velocity + 拍号 + 乐句边界 + 奏法
→ 弓向 + 起弓位置 + 弓长 + 弓速曲线 + 弓压曲线
```

关键规则：

- 强拍优先下弓，但允许为后续乐句提前“倒弓”；
- 连奏组共享一次弓向与弓段预算；
- 断奏需要预留离弦或卸压时间；
- 长音不能只设常量弓速，应允许起音、持续、收音三段曲线；
- 快速音群优先减少无必要的换弦和大幅弓段移动。

比起只输出一个 `bow_speed`，内部中间格式可先使用曲线关键点，Arduino 侧再插值执行。

### 3.3 建立“机器人耳朵”：自动评价每个音

麦克风不仅用于 FFT 测音高，还应生成每个音的质量向量：

| 指标 | 建议算法 | 目标 |
|---|---|---|
| 音高偏差 | 基频跟踪，输出 cents | 稳态区间 ≤ ±5 cents |
| 起音延迟 | 指令时间与有效声起点对齐 | 可重复、逐步压缩 |
| 音量包络 | RMS / LUFS 短时曲线 | 符合力度目标 |
| 杂音比例 | 谐波能量与宽带能量比 | 越低越好 |
| 抖动 | 基频短时方差 | 非揉弦时保持稳定 |
| 断音 / 连奏缝隙 | 相邻包络间隔 | 符合奏法 |
| 音色一致性 | MFCC / 频谱质心距离 | 同类音保持一致 |

每次演奏后保存：

```text
计划动作 + 实际传感器轨迹 + 音频片段 + 质量评分 + 环境信息
```

这会形成项目最重要的资产：**真实机器人演奏数据集**。

### 3.4 自动校准：让机器自己找“甜点区”

不要人工逐项尝试弓速和弓压。对每根弦、不同把位和力度，自动执行安全范围内的小规模探索：

```text
(弓速, 弓压, 接触点, 换弦角度)
→ 演奏单音
→ 计算音准 / 响度 / 杂音 / 稳定性
→ 更新最佳参数
```

早期可用网格搜索；数据积累后升级为贝叶斯优化，在更少试奏次数下找到高质量参数。最终得到的不再是一张手填常量表，而是：

```text
control_parameters =
f(string, pitch, dynamic, articulation, bow_position, environment)
```

建议设置三层参数：

- **出厂基线**：所有设备均可使用的保守参数；
- **本琴校准**：当前琴体、琴弓和执行机构的长期参数；
- **会话校准**：本次温湿度、松香和琴弦状态的短期修正。

### 3.5 数字孪生与安全约束

把 MATLAB 运动学仿真扩展为轻量数字孪生，在真实执行前完成：

- 轨迹可达性检查；
- 电机速度、加速度、冲击峰值估计；
- 左右手机构碰撞预测；
- 弓毛与琴弦接触几何检查；
- 故障注入：丢包、编码器漂移、传感器失真、执行超时。

每条 AI 生成的动作都必须经过“安全投影”：

```text
智能策略输出
→ 限位 / 速度 / 加速度 / 冲突检查
→ 修正为最近的安全动作
→ 下发执行
```

原则是：**AI 可以提出动作，但安全层拥有最终否决权。**

### 3.6 演奏记忆与持续学习

为每首曲目保存版本化的“演奏配方”：

```text
score_version
hardware_profile
calibration_version
planner_version
style_profile
event_plan
quality_report
recording_uri
```

系统可以比较同一曲目的多次演奏，自动回答：

- 哪些音总是偏高或起音失败？
- 哪类换弦最容易产生杂音？
- 最近一次机械调整改善了哪些指标？
- 当前参数在什么温湿度下退化？
- 是全局参数有问题，还是某个音需要局部修正？

这使调试从“凭感觉拧参数”变成可追踪的实验过程。

## 4. 大胆的进阶方向

以下方向不适合立即作为主线，但可以作为项目差异化亮点。

### 4.1 “机器人演奏编译器”

把曲谱转控制指令类比为编译过程：

```text
MIDI / MusicXML
→ 音乐语义 IR
→ 小提琴动作 IR
→ 硬件相关轨迹
→ Violin Event / 实时控制流
```

不同机械版本只替换后端，不重写上层乐谱逻辑；同一个演奏计划还能在仿真器、Arduino 和未来的其他控制器上运行。

### 4.2 教师示范迁移

让真人小提琴手演奏并同步采集音频、弓运动或视频，提取：

- 乐句速度伸缩；
- 弓向与弓段分配；
- 动态包络；
- 揉弦频率与幅度；
- 重音和呼吸位置。

机器人不必复制真人每个关节，而是把示范压缩成自身可执行的风格参数。

### 4.3 自主练琴模式

系统自动循环：

```text
选出最差的 5 个小节
→ 降速分解练习
→ 搜索局部参数
→ 恢复原速
→ 与历史最佳版本对比
```

它像学生一样定位弱点，而不是每次从头播放整首曲子。

### 4.4 自然语言“导演模式”

用户可以输入：

> 第二句更轻一点，结尾做渐慢，高潮处更有张力，但不要增加换把次数。

语言模型只负责把意图翻译为结构化约束：

```json
{
  "phrase": 2,
  "dynamic_scale": 0.82,
  "ending_ritardando": 0.12,
  "climax_energy": 1.18,
  "max_extra_position_changes": 0
}
```

真正的轨迹仍由规划器和安全层生成。这样既保留自然交互，也保证控制确定性。

### 4.5 机器人自己的“审美函数”

除工程指标外，可以邀请小提琴教师对成对录音做偏好选择，训练一个轻量排序模型。其目标不是判断“艺术的真理”，而是帮助系统在多个安全、音准合格的方案中选择更连贯、更自然的一版。

必须保留教师评分、客观指标和模型评分三条独立记录，避免黑盒分数替代真实评价。

## 5. 建议的数据与接口升级

### 5.1 增加演奏计划中间层

V1 的 12 字节事件适合作为传输格式，但不应承担全部规划语义。建议在生成二进制前增加可扩展的 JSON 中间层：

```json
{
  "note_id": 17,
  "tick": 240,
  "duration": 50,
  "pitch": 69,
  "fingering": {
    "string": "A",
    "position": 1,
    "finger": 0
  },
  "bow": {
    "direction": "down",
    "start_ratio": 0.18,
    "end_ratio": 0.62,
    "speed_curve": [[0.0, 3.0], [0.08, 5.0], [0.9, 4.0]],
    "force_curve": [[0.0, 2.0], [0.05, 5.0], [0.95, 3.0]]
  },
  "constraints": {
    "latest_ready_tick": 237,
    "max_pitch_error_cents": 5
  },
  "planner": {
    "version": "0.1.0",
    "cost": 2.74,
    "reason": ["open_string", "avoid_position_change"]
  }
}
```

编译到 V1 时可以降采样为固定字段；未来协议升级时仍保留原始规划信息。

### 5.2 ROS 2 节点建议

```text
/score_parser
      ↓
/phrase_analyzer
      ↓
/motion_planner ─────────→ /safety_supervisor
                               ↓
/performance_evaluator ← /arduino_bridge ← /trajectory_executor
      ↓
/parameter_optimizer
```

推荐主题：

- `/violin/plan`：整段演奏计划；
- `/violin/event_raw`：当前 12 字节事件；
- `/violin/telemetry`：位置、速度、电流、弓压；
- `/violin/audio_features`：基频、响度、噪声比；
- `/violin/quality`：逐音评分与异常标签；
- `/violin/calibration`：参数版本和适用条件；
- `/violin/safety_state`：正常、降级、暂停、急停。

所有消息统一使用单调时钟时间戳，并记录 `note_id`，否则音频与动作数据很难可靠对齐。

## 6. 最小可行闭环：先让一个音“越拉越好”

不要一开始训练复杂神经网络。第一个智能化里程碑建议限定为：

> 固定 A 弦空弦，系统自动搜索弓速和弓压，使连续 10 次演奏的有效起音率、音量稳定性和杂音指标达到阈值。

实施顺序：

1. Arduino 回传实际位置、速度、弓压和时间戳；
2. ROS 2 录制指令、遥测和音频；
3. 音频模块切分单音并计算质量指标；
4. 参数搜索器在安全边界内提出下一组参数；
5. 连续试奏并保存实验记录；
6. 固化最佳参数，换到 D、G、E 弦复测；
7. 再扩展到按弦音、换弦和短乐句。

这个闭环一旦跑通，后续智能化只是扩大状态空间，而不是反复重做架构。

## 7. 分阶段路线图

| 阶段 | 周期建议 | 核心任务 | 验收结果 |
|---|---:|---|---|
| A. 数据可观测 | 1–2 周 | 时间戳、`note_id`、遥测、音频录制 | 可完整回放一次演奏实验 |
| B. 单音质量评价 | 2 周 | 基频、起音、响度、杂音指标 | 自动生成逐音质量报告 |
| C. 自动校准闭环 | 2–3 周 | 安全参数搜索、参数版本管理 | A 空弦能自动找到稳定参数 |
| D. 全局动作规划 | 2–3 周 | 候选图、代价函数、动态规划 | 换弦 / 换把代价低于贪心基线 |
| E. 乐句与弓法规划 | 3–4 周 | 连弓、弓段预算、力度曲线 | 短乐句连贯演奏 |
| F. 自主练琴 | 持续迭代 | 弱点定位、局部重练、历史对比 | 同曲多轮评分持续改善 |

## 8. 可量化验收指标

智能化不能只以“听起来更好”验收。建议同时记录：

### 8.1 控制层

- 事件调度抖动；
- 换弦角度误差；
- 把位重复定位误差；
- 指令到有效起音的延迟及方差；
- 超限、超时、丢包和降级次数。

### 8.2 声学层

- 稳态音高误差中位数及 P95；
- 有效起音率；
- 相同力度下的响度方差；
- 非目标弦共振 / 杂音比例；
- 连奏缝隙和断奏间隔误差。

### 8.3 音乐层

- 不必要换弦次数；
- 不必要换把距离；
- 乐句内动态曲线相关性；
- 教师盲评偏好胜率；
- 同一曲目多轮优化后的评分增量。

每次算法升级必须和固定基线曲目、固定硬件档案比较，避免“换了琴、换了参数，却误以为模型变好了”。

## 9. 风险与边界

| 风险 | 应对 |
|---|---|
| 数据很少就训练复杂模型 | 先用规则、动态规划和贝叶斯优化，数据足够再学习 |
| AI 输出不可预测 | 只输出高层约束，所有动作经过确定性规划与安全检查 |
| 音频评价受环境噪声影响 | 近场麦克风、噪声底标定、同步传感器交叉验证 |
| 只优化单音导致乐句更差 | 单音指标和乐句连续性同时进入目标函数 |
| 参数对某一把琴过拟合 | 参数分为基线、本琴、会话三级并保留适用范围 |
| 协议字段不够用 | 规划 JSON 与传输协议解耦，避免频繁破坏 V1 |
| 自动探索损伤机构或琴弦 | 硬限位、软限位、电流限制、探索预算和人工急停 |

## 10. 下一步建议

按照投入产出比，建议立即开始以下四件事：

1. 给每个音符生成稳定的 `note_id`，打通指令、遥测与音频的时间对齐。
2. 实现单音录音切分和基础质量报告，先建立客观评价能力。
3. 用动态规划替换局部贪心指法选择，并保留可解释的代价明细。
4. 在 A 弦空弦上完成弓速 × 弓压自动搜索，跑通第一个自优化闭环。

一句话愿景：

> 让机器人不只是“把曲谱执行完”，而是能听见自己的问题、知道为什么不好，并在安全边界内把下一遍拉得更好。
