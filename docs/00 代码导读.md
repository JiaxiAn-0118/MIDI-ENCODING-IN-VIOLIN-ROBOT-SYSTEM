# 代码导读（给机械组同学 / 新成员）

> 这份文档是整个项目的"地图"。先看它建立全局印象，再对照各个代码文件里的注释细看。
> 每个代码文件顶部也都有一段"本文件作用"的说明，和这里互相呼应。

---

## 1. 这个项目到底在做什么？

一句话：**让机器人自动拉小提琴**。

我们的做法不是"让机器人听声音"，而是**先把曲子翻译成一串"演奏指令"，再让机械结构照着指令一步步动作**：

- 左手：按住琴弦的某个位置（决定音高）—— 哪根弦、第几把位、用哪根手指；
- 右手：用琴弓拉（决定声音出来）—— 拉还是推、多快、压多紧。

所以整条链路其实是：**乐曲 → 指令 → 机械动作**。下面所有代码都在干这件事。

## 2. 数据流全景图（最重要的一张图）

```
┌──────────────┐    ┌───────────────────────┐    ┌──────────────┐
│  MIDI 乐谱   │ ─> │  violin_midi_json 工具 │ ─> │ .bin 二进制  │
│  (.mid 文件) │    │  (Python，跑在电脑上)  │    │   曲谱       │
└──────────────┘    └───────────────────────┘    └──────┬───────┘
                    解析MIDI→选指法→编码              │ 拷给 ROS2 用
                                                         ▼
┌──────────────────────────────────────────────────────────────────┐
│                     ROS2（在电脑上运行的中间层）                  │
│                                                                  │
│   score_player ──按时序发布事件──>  /violin/event_raw  话题      │
│     (读.bin,到点                  (ROS2里的"消息频道")           │
│      就发一个)                              │ 订阅                │
│                                             ▼                    │
│                                  ┌────────────────────┐          │
│                                  │  arduino_bridge    │          │
│                                  │  (串口桥节点)      │          │
│                                  └─────────┬──────────┘          │
└────────────────────────────────────────────┼─────────────────────┘
                                  USB 串口（每次发 12 字节）
                                             ▼
                                  ┌────────────────────┐
                                  │  Arduino GIGA R1   │
                                  │ giga_serial_bridge │
                                  │ 解码→(将来)驱动电机│
                                  └────────────────────┘
```

**三个阶段**：

| 阶段 | 在哪运行 | 做什么 | 涉及代码 |
|------|---------|--------|---------|
| ① 生成曲谱 | 电脑（一次性） | 把 `.mid` 转成 `.bin` 二进制曲谱 | `violin_midi_json/` |
| ② 播放与转发 | 电脑（运行时） | 按时序把指令发给 Arduino | `ros2_ws/` |
| ③ 执行动作 | Arduino（硬件） | 解码指令、控制电机 | `firmware/arduino/` |

> 另外 `simulation/simu_final.m` 是**机械设计阶段的动力学与选型仿真**，
> 用来确定电机扭矩/功率、导轨行程与颠覆力矩等硬件参数，和上面三条线是并行的"设计工具"。

## 3. 12 字节协议速查（贯穿全链路的"通用语言"）

电脑和 Arduino 之间，每个音符都打包成一个 **12 字节**的数据包。这是全项目最核心的约定，
详细定义见 [Binary_Violin_Event_Protocol_V1.md](./Binary_Violin_Event_Protocol_V1.md)。

| 字节 | 字段 | 含义 |
|----:|------|------|
| 0 | Header | 固定包头 `0xA5`（看到它就知道新包开始了） |
| 1-2 | Tick | 触发时刻（1 tick = 10 ms，低字节在前） |
| 3 | Pitch | MIDI 音高（如 69 = A4） |
| 4-5 | Duration | 持续时长（单位 tick，低字节在前） |
| 6 | 弦/手指/把位 | 一个字节塞 3 个信息：高2位=弦 中3位=手指 低3位=把位 |
| 7 | 弓方向/弓速 | 最高1位=方向(0拉/1推) 低7位=弓速 |
| 8 | Force | 弓的压力力度 |
| 9 | Flags | 演奏法标记（揉弦/连奏…，目前为 0） |
| 10 | Reserved | 预留 |
| 11 | Checksum | 校验和（前 11 字节相加取低 8 位，用来查传输错误） |

编码端（电脑）：[binary_encoder.py](../violin_midi_json/src/violin_midi_json/binary_encoder.py)
解码端（ROS2）：[protocol.py](../ros2_ws/src/violin_ros_bridge/violin_ros_bridge/protocol.py)
解码端（Arduino）：[giga_serial_bridge.ino](../firmware/arduino/giga_serial_bridge/giga_serial_bridge.ino)
—— 三处用的是**同一套位运算**，互为正反操作。

## 5. 术语表（看到不懂的词来这里查）

### 音乐 / 小提琴

| 术语 | 含义 |
|------|------|
| **MIDI** | 电子音乐的标准格式，每个音用数字表示，`.mid` 文件存的就是一串数字音符 |
| **pitch（音高）** | MIDI 里的音高编号，如 69 = A4（标准音 la）。每 +1 升高半音 |
| **tick** | 本项目的时间单位，1 tick = 10 ms。曲子里"第几个 tick 做什么" |
| **弦（string）** | 小提琴 4 根弦，从低到高 G D A E，编号 0 1 2 3 |
| **把位（position）** | 左手在琴颈上的上下位置，第 1 把位最靠近琴头、最常用 |
| **手指（finger）** | 0=空弦(不按) 1=食指 2=中指 3=无名 4=小指 |
| **运弓（bow）** | 右手拉弓：方向(拉/推) + 速度 + 压力 |

### 计算机 / 通信

| 术语 | 含义 |
|------|------|
| **串口（serial）** | 一种最基础的通信方式，一字节一字节地传；这里走 USB 线 |
| **波特率（baud）** | 串口通信速度，收发双方必须设成一样（本项目用 115200） |
| **包头（header）** | `0xA5`，每个数据包开头的标志，用来"对齐"——收到它就知道新包开始了 |
| **校验和（checksum）** | 把数据字节相加得到的一个数，接收方重算对比，用来查传输有没有出错 |
| **小端序** | 一个多字节数"先存低字节、再存高字节"的排列方式（见编码/解码处的注释） |

### ROS2（机器人操作系统）

| 术语 | 含义 |
|------|------|
| **节点（Node）** | ROS2 里一个独立运行的小程序（如 score_player 就是一个节点） |
| **话题（Topic）** | 节点之间传消息的"频道"，有名字（如 `/violin/event_raw`） |
| **发布（publish）** | 往话题里发消息 |
| **订阅（subscribe）** | 盯着话题收消息，一有新消息就自动处理 |
| **launch 文件** | 一键启动脚本，按预设把多个节点配好参数同时跑起来 |

### 机械

| 术语 | 含义 |
|------|------|
| **正运动学** | 已知电机角度 → 求末端(琴弓)位置（由因到果） |
| **逆运动学（IK）** | 已知末端位置 → 求电机角度（由果到因，仿真里干这个） |
| **工作空间** | 机构"够得到"的位置范围；轨迹超出它就拉不动 |
| **余弦定理** | 仿真里用来由三角形三边关系反推关节角度的数学公式 |

## 6. 建议阅读路线

### 机械组同学
1. 先读本文件建立全局印象；
2. 看 `simulation/simu_final.m`（狗腿机构动力学 + 选型，纯机械内容，文件头有术语速查）；
3. 再看 `firmware/arduino/giga_serial_bridge.ino`（硬件怎么收指令）；
4. Python 部分了解即可，重点看文件头的"本文件作用"和 `binary_encoder.py` 的协议部分。

### 软件 / 电控组同学
1. 先读本文件 + [协议文档](./Binary_Violin_Event_Protocol_V1.md)；
2. 按数据流顺序读：`violin_midi_json/` → `ros2_ws/` → `firmware/`；
3. 跑通测试：先 `mock_demo`（无硬件）再 `serial_demo`（接硬件）。

  scores/小星星/小星星完整版.mid scores/小星星/小星星完整版.bin \
  --format bin --title "小星星完整版"

```bash

# 接真 Arduino
ros2 launch violin_ros_bridge serial_demo.launch.py score_path:=/path/to/曲谱.bin
```
